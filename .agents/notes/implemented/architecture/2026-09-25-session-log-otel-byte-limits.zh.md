# Agent Note: Session 日志的 OTLP 字符串与有界请求

Status: implemented

[English](2026-09-25-session-log-otel-byte-limits.md) | 中文

## 问题

Session 日志包含嵌套 JSON 和大型工具结果。产品采集端接收带名称和字符串内容的记录，并限制请求大小；仅按数量分批的 SDK 无法约束 UTF-8 编码与 JSON 转义后的字节数。

## 决策

产品 OTel 包提供一个由其服务和反馈后端共享的 Session 日志上报器。每条规范事件转换为 `eventName: "session-log"`，属性包含 `sessionId` 和存放完整事件 JSON 字符串的 `content`。脱敏在序列化前执行；采集记录携带不重复包含载荷的信封。

Session 日志使用专属 SDK provider 和队列。导出器使用传输的 SDK 序列化器计量完整未压缩 OTLP JSON，并将批次拆分到最多 4,000,000 字节。单条超限事件被拒绝并记录诊断，不阻止其他事件发送。该队列禁用属性截断。拥有方提供有界关闭过程，等待拆分导出完成。

[遥测恢复决策](../feature/2026-07-23-session-telemetry-otel-revival.zh.md) 仍负责脱敏、采集和尽力交接。本决策在 Session 日志请求计量方面替代其仅由 SDK 分批的规则；SDK 仍负责排队节奏和传输重试。反馈授权与独立的 DeepSeek 模型请求贡献保持不变。

## 考虑过的替代方案

**整个 Session 合为一个字符串。** 拒绝，因为即使每条事件都能放入请求，大型 Session 仍会超过请求上限。每条事件对应一条记录，既保留事件身份又允许分批。

**截断超限记录或仅在客户端分片。** 拒绝，因为截断会丢失内容，而分片需要采集端重组协议。显式拒绝保留一条事件对应一条记录的含义。

**计算压缩字节数或字符数。** 拒绝，因为采集端限制可能作用于解压后内容，而字符数不包含 UTF-8 和转义开销。计量完整未压缩请求提供保守上限。

## 影响

产品与 Session 记录共享路由配置，但绝不共用请求。队列溢出、单条事件拒绝、进程退出和传输失败仍可能丢失数据；不增加持久化 outbox 或采集端确认。测试观察精确字节上限、嵌套 JSON 往返、请求分离、超限后继续发送，以及反馈授权的录制会话回放。
