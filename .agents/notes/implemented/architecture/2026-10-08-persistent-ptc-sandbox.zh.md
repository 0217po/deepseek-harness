# Agent Note: 保留状态的 PTC 进程遵循文件策略

Status: implemented

[English](2026-10-08-persistent-ptc-sandbox.md) | 中文

## 问题

保留 JavaScript 变量不需要更大的文件访问权限。跨调用存活的进程也可能在单次审批结束或 Session 策略变化后继续运行。权限结束后，其文件句柄和后台工作不能继续持有原权限。

## 决策

`persistent-in-memory` 与 `per-call` 通过同一个沙箱提供方启动 Node 进程。保留状态的所有者在释放前使用固定的已解析权限模式、工作区根目录和 Session 身份。[内存决策](2026-09-23-best-effort-persistent-ptc.zh.md)负责保留值、失败恢复和包组成；本文负责文件权限。

文件策略服务负责模式切换。PTC 在审批或目录解析前登记 Session 执行；Node 按已解析策略中的 Session 身份登记每个进程的清理操作。`sandboxPolicy.setMode()` 阻止新调用、取消已登记调用，并在登记资源清理完成后记录新模式。清理失败会阻止切换。仍有登记资源或操作时，直接追加沙箱事件会被拒绝。权限预设和直接选择模式的调用方使用同一个 setter。工具包保留 Agent 所有权，并在临时提权时省略所有者；它不依赖权限预设。

单次获准的提权省略状态所有者，使用全新的临时环境。该次调用返回前释放进程，无法访问原环境的变量，也不会保留新声明。原环境保持原权限和变量。嵌套工具继续应用各自的权限和审批规则。

## 考虑过的替代方案

**不限制保留状态的执行环境。** 省略沙箱能简化临时原型，却把变量保留与完整宿主文件访问权限绑定。现有进程沙箱支持长期运行的进程，因此这项授权没有必要。

**修改运行中进程的策略。** 现有后端在启动时应用限制。现有接口无法把任意保留对象、打开的句柄和后台工作转移到另一策略。释放环境让权限切换具有确定的完成时点。

**通过权限预设协调清理。** 文件策略也有直接调用方。文件策略所有者为两类调用方提供同一个清理操作，工具注册表不需要了解面向用户的预设选择。

**保留提权环境。** 单次审批不能授权未来程序或空闲期间的后台工作。省略状态所有者明确了审批生效的范围，同时保留原环境。

## 影响

普通调用保留变量，同时维持原文件权限。切换沙箱模式会丢弃变量，并在权限命令结果中提示。提权程序必须包含执行所需的完整代码。运行时消费者在传入不同策略前必须释放保留状态的所有者；提供方拒绝策略不一致的复用。沙箱继承现有后端的文件约束范围与平台限制。
