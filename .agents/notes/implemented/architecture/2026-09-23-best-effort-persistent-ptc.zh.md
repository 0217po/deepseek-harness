# Agent Note: 尽力保留的持久 PTC 内存

Status: implemented

[English](2026-09-23-best-effort-persistent-ptc.md) | 中文

## Problem

交互式自动化需要在模型调用之间保留应用对象、导入模块和辅助函数。每个程序都重新创建对象，会使消费者无法在观察和操作之间使用普通 JavaScript 引用。

## Decision

可选提供方 `dsh-ptc-runtime-node/persistent` 为每个以对象身份标识的显式状态所有者保留无沙盒 Node REPL 进程。PTC 使用存活 Agent 作为所有者，并在其上下文销毁时等待释放。默认的[沙盒提供方](2026-09-11-sandboxed-node-ptc-runtime.zh.md)保留每次启动新进程的行为。此决定为 [PTC 基础](../feature/2026-06-15-ptc.zh.md)增加可丢失的内存，同时保留注册表分派和模型请求日志。

Session 记录提交的程序、嵌套工具调用和返回输出。它不序列化 REPL 堆，也不在重启、恢复或派生后重跑以前的程序，因为回放自动化可能重复外部副作用。缺失变量是普通程序错误，模型可见说明要求重新创建变量和获取资源。提供方没有暴露未记录的模型输入，因此不需要环境标识符或新的持久 Session 事件。

取消、截止到期、协议失败、输出超限、所有者销毁和进程退出会丢弃环境。普通异常保留此前发生的修改。保留的函数使用当前执行的宿主绑定；较早执行产生的异步工作不能取得后续执行的工具权限或输出接收器。

## Alternatives considered

序列化任意 JavaScript 对象无法保留原生资源和闭包。回放以前的程序可能重复写入和输入操作。这两种方案都会隐含本提供方没有承诺的恢复保证。

Harness 进程内的执行域与模型代码共享进程寿命，无法单独终止同步循环。受管子进程允许取消和资源清理，同时在正常使用时保留导入模块和变量。该进程不提供文件沙盒或多租户安全隔离。

## Consequences

启用提供方会允许直接 Node 代码完全访问宿主。它需要显式启用，拒绝显式沙盒策略，嵌套工具继续遵循原有授权和日志规则。即使 Harness 没有重启，内存和原生句柄也可能丢失。模型必须从引用错误或资源错误中恢复；运行时不会自动重试程序。

空闲所有者保留进程，没有过期计时器。调用方显式释放所有者；没有所有者的服务调用使用临时进程。程序使用 REPL 语句和末尾表达式，不能使用顶层 return；同一保留环境的调用不能重叠。
