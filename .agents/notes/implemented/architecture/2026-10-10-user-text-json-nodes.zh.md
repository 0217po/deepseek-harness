# Agent Note: 用户文本线性变换、Facts 依赖与业务节点渲染

Status: implemented

[English](<2026-10-10-user-text-json-nodes.md>) | 中文

## 问题

用户文本包含普通文字和不同业务的结构化引用。业务需要独立扩展识别逻辑、JSON 数据与显示方式；某个事实字段更新时，无关业务不能重复匹配。处理结果必须确定，且文本处理、缓存和依赖记录不能与 React 组件生命周期耦合。

## 决策

采用“业务注册 → 线性分段变换 → 纯 JSON 节点 → keyed Slot → 业务 Slot 自身 Injection”。现有 UserText 注册机制负责组成流水线，数据层运行器负责求值与增量更新，React 只显示最终节点。

### 线性流水线

非空原文初始化为一个覆盖 `[0, text.length)` 的 Text 分段；空原文对应空数组。注册项仅按 `order` 升序、同序号按稳定注册 ID 排列，不依赖插件加载时机，也不按处理类别分组。每个阶段对前一阶段的结果执行一次同步 `transform`，不另设多轮 pass 或重复执行至稳定点。规则的先后关系由其注册顺序值明确表达。

每一层接收当前完整的只读分段数组。不属于它处理的分段保持原引用；需要变化的部分产生新对象。文本识别针对当前可处理的 Text 分段进行，已形成的业务节点保持原子性并传递到后面。不能让所有规则独立匹配初始全文，再靠全局候选排序代替逐层变换。

原文不被修改，输出保持原始 UTF-16 坐标。每层输出有序、非重叠并覆盖相同原文范围；替换节点保留它消费的范围。业务不能把被结构化节点隔开的文字重新拼成相邻文本，也不能扫描前一层的 JSX 或显示标签。

### Transform 与读取 Context

注册项包含唯一注册 ID、顺序和变换函数。新增业务节点使用该规则 ID；仅加工 Text 显示值的规则不需要对应的业务节点或 renderer。所有规则使用同一套原文覆盖和业务节点保护约束。核心接口为：

```ts
import type { UserTextFacts, UserTextNode } from '@deepseek-ai/dsh-client-ui-conversation/client'

interface UserTextTransformContext {
  read<K extends keyof UserTextFacts>(
    key: K,
  ): UserTextFacts[K] | undefined
}

interface UserTextRule<Id extends string = string> {
  readonly id: Id
  readonly order: number
  transform(
    segments: readonly UserTextNode[],
    context: UserTextTransformContext,
  ): readonly UserTextNode[]
}
```

Context 是本次同步求值的事实读取器和依赖记录器，不是 Cordis Context、React Context 或服务定位器。它只提供只读 Facts 字段，不提供打开文件、导航、附件加载等动作，也不能保留到本次求值之外使用。

业务不直接获得完整 Facts 对象，不维护独立的 `dependsOn` 声明，也不接收 `previous` 或缓存对象。匹配、正则、查表等是各业务变换函数内部的实现方式，不是公共运行器的业务分支。

### 实际读取依赖

运行器为每次阶段求值创建读取记录。`context.read(key)` 返回本次 Facts 快照中的值，同时记录该字段及其版本或值引用。读取结果为 `undefined` 也建立依赖，字段以后出现时能够重新触发计算。

每次执行重新收集实际读取集合，替换旧记录，不永久累积已经不再读取的字段。业务可以在不相关的输入上提前返回；未执行 `read('skillNames')` 的阶段不因该字段变化而失效。

依赖粒度是 Facts 字段。读取 `skillNames` 表示依赖这个字段，不自动追踪数组中的单个元素。字段以不可变数据更新；外层 Facts 对象换引用不等于全部字段变化。

### 增量更新与缓存

运行器为每份文档、每个阶段保存输入分段、实际读取的字段及其版本、规则版本和输出分段，并维护“Facts 字段 → 读取它的阶段”的反向索引。线性顺序已经表达上游关系，不建立任意形状的通用依赖图。

Facts 更新时，只将实际读取了变化字段的阶段标记为失效。运行器按流水线顺序执行：阶段自身依赖变化、规则变化或上游输出变化时才重算；否则直接复用缓存。某层输出不变时，停止由它引起的下游失效，但后面直接读取了其他变化字段的阶段仍然执行。

原文变化使全部阶段重新计算，从单一初始 Text 分段开始，不要求字符级增量解析。规则增加、删除、重排或实现更新时，从最早受影响的阶段重新求值；此前未受影响的缓存可以复用。

缓存由文档所属的数据层求值实例拥有。注册表创建文档求值回调但不保存该回调或文档，也不为文档增加注册表订阅；显示绑定释放回调后，文档缓存随之释放。不同文本实例不共享计算器，不按原文字符串跨 Session 共享缓存。未挂载历史内容不需要为显示规则更新重新读取 Session 日志。

### 引用复用与确定性

输入数组、节点和 Facts 使用 TypeScript readonly 类型；运行器借用这些值，不冻结或复制它们。禁止原地 `splice` 输入、修改节点 payload 或通过保留引用写入后续结果。不变的输入节点继续复用；结果完全不变时保留数组引用，不以全量深拷贝作为隔离方法。

运行器内部保存上一轮输出，用于对齐重算结果。业务产生的新节点与旧节点在 ID、原文范围及 JSON 数据上等价时，可以复用旧对象；全部结果元素相同时复用旧数组。比较只发生在需要重算的阶段，先使用引用相等的快速路径，不在每次刷新时序列化整条流水线。

旧结果只用于运行器复用对象，不参与业务判断。相同原文、规则顺序和 Facts 快照，无论首次计算、重复计算还是增量更新，必须得到相同的 JSON 内容。

### Facts 与显示 Props

文档运行器只接收 `{ text, facts }`。Facts 只保存 transform 实际需要的业务上下文和处理参数，通过 `Context.read` 消费；不因为某个值属于配置就把它放入 Facts。UserText 的交互、CSS 省略等纯显示行为使用普通 React Props，运行器不读取它们。核心不按正文、队列或 Goal 等场景名称分支。

节点外壳为 `{ id, start, end, data }`。`id` 是业务类型，对应节点 Slot 的 key；`start`、`end` 表示原文的非空半开 UTF-16 范围；`data` 是该业务的 JSON payload。Text 的 `data.text` 始终保留原文，`data.display` 是可选显示文字。普通 transform 可以写入显示值或进行合法 Text 分段变换，但不能改变原文、破坏覆盖或消费已有业务节点。节点实例身份由文档内的业务 ID 与原文位置表达，不能只用业务 ID 或数组下标。

节点和 Facts 不包含函数、ReactNode、服务句柄、DOM、observable、Date 或 Map。`UserTextDataMap` 与 `UserTextFacts` 是公开 `/client` 入口上的可扩展声明实体，内部类型引用同一实体；业务声明合并必须保留在发布的类型文件中。JSON 兼容性由类型约束与单测保证，可信同进程输入不逐次做整树序列化校验。

业务 Facts 由调用者提供，不是运行器自行查询的全局状态：skill 使用已确认的名字，会话引用使用关联标签，命令使用真实执行范围。普通文件路径可以只依据文本识别；附件显示名不等于文件路径，不据此猜 attachmentId。

`collapseWhitespace` 与 `trimWhitespace` 分别控制两个文本显示变换，缺省均不启用。每条规则只读取自己的开关并使用前一层的显示结果；空白折叠跨连续 Text 分段延续但不跨业务节点，trim 只处理整份文档两端而不删除引用之间的正常空格。内置规则用普通 `order` 值将这些加工安排在既有引用识别之后，保留引用内部字符和身份；不存在额外的类别优先级。

`interactive` 和 CSS `ellipsis` 由 React Props 传递，不属于 Facts。省略不删除原文或限制传入字符数。队列用 Facts 启用空白折叠与 trim，用显示 Props 启用省略；消息正文与 Goal 保持完整展示。调用者不再保留 `previewOf`、200 字符预截断或未知块占位拼接，非文本附件继续走既有附件展示。

引用摘要从 `UserContentData.referenceLabels` 获取显示数据，不读取 Facts。会话引用变换仍通过 `Context.read('sessionLabels')` 获取识别输入。调用者把同一标签数组按引用分别传给这两个消费者，不复制数组，也不建立第二份状态。

### 渲染与交互所有权

`conversation.user.text` 是 session 作用域 Factory，独立拥有 session/keyed 的 `conversation.user.text.node`。UserText 顺序遍历最终节点，以节点 ID 选择 renderer，不包含 skill 或 file 的集中渲染分支。默认条目使用 `priority: 100`，外部业务按既有 Slot 机制覆盖对应 key。

`text` 和会话标签由 `ui-conversation` 提供，skill 由 `ui-skill` 提供，普通文件及目录引用由 `ui-reference` 提供，Goal 命令标记由 `ui-goal` 提供。业务自己的 Slot 注册声明操作依赖；解析数据不携带回调，上层布局不转交这些节点专用动作。

显示侧将 `interactive` Prop 连同原文片段 `raw` 传给节点 renderer；这些都是普通数据，不是执行能力。只有 `interactive` 为 true 时允许显示引用操作。队列、提交回显及待接收输入保持不可点击；会话、目录和命令默认仍为标签。原生附件不进入文本流水线：文件卡片保留名称和大小，图片画廊使用既有 Session 授权 loader。

文件导航失败由文件引用业务处理，不回到 Chat 动作聚合层。局部 Modal 提供重试和关闭；同步导航不增加请求序号或虚构 abort。文件读取错误仍由文档预览处理，Sidebar 继续使用现有公共定位语义。Assistant Markdown 的既有反馈与组件分工独立保留。

行内节点 Slot 使用 `inline: true` 的 span 锚点及行内错误占位，保留 `data-slot` 和 `display: contents`；其他 Slot 默认 DOM 不变。文字选择、键盘激活、双击不误打开、换行和队列省略策略保留。这里不引入业务 Context、React 变换阶段或通用注入继承。

### 发布与失败

只有完整成功的求值结果可以发布。失败不发布部分分段，显示层保留原文并报告业务 ID；失败执行中已读取的字段仍用于后续重试依赖。缺少节点 renderer 时回退到该节点的原文片段，组件异常使用框架既有隔离机制。

React 通过现有框架获知规则版本变化，将当前原文与 Facts 交给独立的文档求值回调，只消费最终节点结果。阶段依赖、缓存更新和结果对齐全部在数据层；显示层不通过 effect 回传输入或分段，节点数组未变时复用渲染元素。规则卸载撤销其注册，文档下次求值移除相应依赖；事实读取 Context 不得泄漏到节点或显示组件。

### 范围

UserContent 保留附件、正文容器、未知内容和引用摘要，消息外壳继续拥有 key、时间、复制与 pending/echo。Queue、Goal 与 Chat 复用 UserText 的数据处理和渲染入口。原生附件列表的 loader、草稿编辑模型、Session 持久化原文及 Assistant 分工不归本流水线重构。

## 验证要求

- 注册新业务只需提供变换、JSON 类型及 keyed renderer，公共运行器和 UserText 无需新增业务分支。
- 前置规则认领文本后，后续规则以实际剩余分段计算，不使用初始全文候选冒充当前匹配结果。
- 未读取的 Facts 字段变化不会执行该阶段；读取缺失字段后，该字段出现能够触发重算；条件读取关系可以增加或撤销。
- 某阶段读到的 Facts 变化但输出等价时，旧节点和数组引用得到复用，无关下游不执行；直接依赖其他变化字段的后续阶段仍然执行。
- 原文变更完整执行流水线；增量结果与相同输入下的新建求值实例结果一致。
- 只读类型断言覆盖数组和 payload；节点输出有序、完整覆盖原文、无重叠并可作 JSON round-trip。
- 顺序仅由 `order/id` 决定；内置显示变换的普通注册顺序、独立开关、相邻分段空白、文档边缘 trim、emoji 保留和引用原子性均由变换单测覆盖。
- 文本处理不执行 UI 操作；preview 不因 Slot 注入了操作能力而变成可点击；注册与卸载不泄漏求值状态或订阅。

## 备选方案

**全文独立匹配后全局仲裁。** 它不能表达前置规则消费文本后各阶段的实际输入。

**React 组件变换链。** 文本处理、依赖记录和缓存不能绑定显示生命周期。

## 影响

字段级依赖不承诺字段内部逐元素失效；某层读取的字段变化仍可能要求该层执行。结果对齐也有比较成本，不能将引用复用称为零计算。任意规则更新可能影响之前的普通文字，不能仅按已有业务节点 ID 过滤历史更新。各业务必须遵守只读输入和同步确定性协议；外部可变状态、隐藏读取或异步使用 Context 会破坏依赖正确性。文件反馈归属改变和行内 Slot 行为需要独立的显示层验证，不以数据层测试代替。
