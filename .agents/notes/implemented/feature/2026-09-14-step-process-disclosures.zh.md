# Agent Note: Assistant 回复之间的过程折叠

Status: implemented

[English](2026-09-14-step-process-disclosures.md) | 中文

## Problem

整轮折叠只能缩短已经完成的轮次。较长的进行中轮次会在可读的进度回复之间穿插工具与推理详情，让用户难以找到下一条回复。

## Decision

[Chat 渲染器](../../../../packages/client/ui-chat/README.zh.md#turn-process-folding) 将 Assistant 回复之间的连续过程内容分组。同一 Assistant 节点中的推理与回复块使用独立的渲染位置，因此流式正文会闭合前面的过程组，同时保持回复外露。分组以首个成员的键保持更新前后的展开状态，现有整轮折叠仍负责外层可见性。其标题展示记录的轮次起止时间之间的用时，时间戳缺失时省略时长。

标题汇总模型工作，不汇总基础设施记录。读取与编辑分别按已知文件路径去重，命令和搜索按调用次数计数。数量最多的三类按降序显示，数量相同时按首次出现顺序排序。未知工具计入通用工具类别。进行中的分组描述最后一个仍在运行的工具，调用间隙回退为思考状态。展开内容设有与视口相关的高度上限，并在内部滚动。

整轮折叠按轮次独立判断：历史分页未加载完时，该轮起点必须已加载。要求整个 Session 历史加载完整会让长时间运行的 goal 和 job 会话无法折叠。补齐起点即可启用该轮折叠，无需等待无关的更早轮次。

## Alternatives considered

**等到轮次结束。** 用户阅读进行中的进度时，详情仍然占据大量空间。

**将每个 Assistant 节点都视为不可拆分的回复。** 纯推理步骤以及流式正文之前的推理会留在过程折叠之外。

**在摘要中加入基础设施标签。** 提示词组装、上下文注入与权限元数据不能描述模型工作，还会降低紧凑标题的可读性。

## Consequences

分组仅改变展示，不增加 Session 事件或模型输入。临时分类由工具名决定，因此自定义工具计入通用类别，缺失文件路径时按调用计数。展开状态保存在当前挂载的聊天视图中。分页改变分组首个成员时可能重置展开状态。各工具原有的独立折叠仍可在限高过程区内使用。
