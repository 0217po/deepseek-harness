# Agent Note: Windows 卸载时按需清除数据

Status: implemented

English | [中文](2026-09-18-windows-opt-in-uninstall-data.md)

## Problem

Desktop 和 CLI 共享 Harness 主目录中的会话、凭据和设置。配置档案数量不能证明数据由 Desktop 独占：CLI 配置档案按需创建。浏览器存储和更新下载还位于主目录之外。

## Decision

Windows 卸载默认保留数据。用户可以选择桌面浏览器数据与更新缓存、仅 `profiles/desktop` 或整个 Harness 主目录。选择整个主目录需要原生警告确认，显示实际路径及 CLI 影响，默认选择取消，并强制勾选桌面子项。取消父项勾选会恢复子项先前的独立状态。静默卸载和升级不会选择清除数据。

最近一次打包 Desktop 启动将解析后的主目录写入 Electron 用户数据中的 INI 文件。长度字段检测 NSIS 读取截断。旧安装缺少记录时选择默认主目录；无效记录不能授权删除主目录。原生清理拒绝受保护的根目录及与安装目录重叠的路径，遍历时持有目录句柄防止路径被替换，遇到后代重解析点只移除链接，不遍历目标。失败会停止卸载，并说明可能已经删除部分数据。此操作仅针对当前用户，不清理所有用户。

[旧提案](../../rejected/feature/2026-09-08-desktop-uninstall-preserve-dsh-home.zh.md)中无条件删除外部数据的方案由显式选择替代。macOS 清理不属于本次实现。现有 Desktop 打包及配置档案归属决策仍然适用。

## Alternatives considered

**只有 desktop 配置档案时删除整个主目录。** 配置档案是否存在不能证明 CLI 或重新安装时不需要共享数据。

**始终保留主目录并自动删除外部缓存。** 浏览器存储包含草稿和偏好，应由用户选择是否删除。用户也可以明确选择丢弃全部共享数据。

**使用 electron-builder 的 delete-app-data 开关。** 它没有父子选择、共享主目录警告和更新缓存清单；清理由交互式自定义页面控制。

## Consequences

仅清理桌面配置档案可能保留 Office 运行环境及共享数据。整个主目录选项会删除显示根目录中的所有文件，包括用户自行添加的文件。不会发现或删除其他历史主目录、任意插件输出和所选根目录之外的用户项目。

验收使用独立产品身份。源码回归覆盖 INI 持久化和模板适配；原生夹具覆盖保留、分项删除、目录链接目标及升级和静默行为。开发主机的 Application Control 阻止未签名的测试卸载器，因此该主机尚未验证原生执行、已安装发布产物清单和高 DPI 视觉效果。仅编译通过不等于发布验收通过。
