# Agent Note: Windows 卸载保留 Harness 主目录

Status: implemented

[English](2026-09-18-windows-uninstall-retains-harness-home.md) | 中文

## 问题

Desktop 和 CLI 在 Harness 主目录中共享会话、凭据、设置和插件。Electron 把浏览器存储和缓存放在 `%APPDATA%` 下，更新器把下载的安装包放在 `%LOCALAPPDATA%` 下；上游 NSIS 模板在没有命令行参数时会把两者都留下。卸载的用户期望应用不留残余，重装的用户期望会话仍在。

## 决策

Windows 卸载随应用一起删除 Electron 用户数据目录、`%APPDATA%` 下的产品目录和更新器缓存，从不触碰 Harness 主目录。卸载程序没有自定义页面；静默卸载删除相同的数据，升级卸载保留数据，使自动更新保留界面偏好。Electron 根据带作用域的包名派生用户数据目录，因此删除目标是 `%APPDATA%\@deepseek-ai\dsh-desktop`，随后移除已空的作用域目录。删除通过 `window-frame.dll` 中的原生辅助程序执行：它拒绝受保护的 Windows 目录和与安装目录重叠的路径，遍历期间持有目录句柄，遇到重解析点只解除链接而不进入目标。失败写入卸载日志，不中止卸载。

2026-09-08 的提案（保留主目录、删除外部应用状态）以这一形式在 Windows 上被采纳；其中的 macOS 辅助程序和已安装产物清单方案未被采纳。安装时还会在 Windows 卸载注册项上记录 `InstallLocation` 作为标准的清单元数据。Windows 11 上 Win32 安装包无法让开始菜单右键菜单中的“卸载”直接启动卸载程序，只有 MSIX 包能做到，因此该需求不在本决策范围内。

## 备选方案

**在自定义卸载页上按需删除，包括桌面配置档案和整个主目录。** 桌面配置档案、会话和凭据属于与 CLI 共享的主目录，为重装而保留；剩余的 Electron 数据只包含界面偏好和缓存，不值得让用户理解并做出选择，也不值得为卸载程序记录主目录路径并维护双语原生对话框。

**当桌面是唯一配置档案时删除整个主目录。** 配置档案的存在不能证明共享数据是否被 CLI 或将来的重装需要。

**沿用上游默认，保留 Electron 数据。** Chromium 缓存会增长到数百 MB，正是用户卸载后反馈的残余。

**使用 electron-builder 的 `deleteAppDataOnUninstall`。** 上游的 `RMDir /r` 不遵守归属规则、不支持长路径并会进入链接目录；改由原生辅助程序负责删除。

## 结果

重装恢复会话、设置和插件，但不恢复界面布局偏好。主目录下的桌面配置档案及其包和锁文件保留。其他历史主目录和用户项目不会被发现或删除。

验收使用带作用域包名的隔离产品身份。源码回归覆盖模板适配；原生夹具覆盖主目录保留、用户数据、作用域目录和更新器缓存的删除、junction 目标、静默与升级行为。标准卸载页面的高 DPI 视觉验收仍未完成。
