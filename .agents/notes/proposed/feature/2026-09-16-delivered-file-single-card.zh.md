# Agent Note: 交付的改动文件只显示一张卡片

Status: proposed

[English](2026-09-16-delivered-file-single-card.md) | 中文

## 问题

一轮结束时有两个文件区块：[改动文件卡片](../../implemented/feature/2026-09-11-turn-changed-files-card.zh.md)列出本轮改动的每个文件及其增删行数，并在该文件上打开 [review tab](../../implemented/feature/2026-09-15-changed-file-diff-preview.zh.md)；模型通过 [present](../../implemented/feature/2026-09-08-present-workspace-source-files.zh.md) 声明的每个文件有一张交付卡片，在 Sidebar 中预览并用原生应用打开。本轮既改动又交付的文件在两处都出现，第二次出现没有给用户任何新信息；录制的 `changed-files-turn` 场景里四个文件显示为四行加四张卡片。

两个区块提供的东西和寿命都不同。行有行数和对比；卡片有模型写的说明、预览和原生操作。卡片的内容只活在 Host 进程里，Host 重启后重新打开的会话没有改动文件卡片，而 `deliverables/presented` 事件持久化在 Session log 里，它们的卡片会回来。

## 提议

本轮既改动又交付的文件只显示一次，显示在交付卡片上。改动文件卡片去掉该文件的行，保留头部；头部仍写本轮完整的文件数和汇总行数，仍在本轮上打开 review；所有改动文件都被交付时只剩头部。交付卡片在文件名旁补上该文件的增删行数，或二进制、过大标签，点击该标签在该文件上打开 review tab，这样对比、预览、原生操作和说明都从同一处可达。只改动或只交付的文件照旧显示，不同轮次之间不共享数据。

匹配在 Client 渲染时按词法进行：分隔符统一为 `/`，去掉 `.` 段，折叠 `..`，落在 Session 工作目录下的绝对路径改写为相对路径。同一轮内重复交付同一文件按同一个键合并，保留最新的说明。只经软链才相同的两种拼写保持不同。

持久化的东西都不变：没有新的 Session 事件、没有 Host 路由、recorder 不改；合并逻辑放在 `packages/client/ui-deliverables` 里卡片推导的旁边。Host 重启后改动文件卡片不存在，交付卡片按现在的方式渲染，不需要特殊处理。

## 考虑过的替代方案

**保留行、去掉卡片**代码更少，但交付物的默认入口从预览变成对比：一份报告或 SVG 变成一行 diff，二进制交付物变成一个「二进制」标签，完全没有预览。

**让模型不要 `present` 改动文件卡片会列出的文件**行不通：`workspace/changes` 事件从不进模型上下文，它的覆盖范围取决于 git、ignore 规则、文件数上限和临时目录排除；`present` 由 `standard`、`ptc`、`cordis` 三个 preset 共用，它们的 headless 和 SDK 消费者没有改动文件卡片；Host 重启后没交付的文件就没有任何入口。工具描述也要求交付用户要的每个产出，这是[交付决定](../../implemented/feature/2026-09-08-present-workspace-source-files.zh.md)定下的。

**一张合并卡片**，列出每个改动文件并在被交付的行上放交付操作，会把两个寿命不同的区块并成一个，并重开卡片设计；本提议保留两个区块，只挪走重复的那份。

## 验收标准

- 同一轮既改动又交付的文件只显示一张交付卡片，没有改动文件行；头部的数量和汇总仍包含它。
- 交付卡片显示该文件的行数，点击该标签在该文件上打开本轮的 review tab；预览、原生操作和说明都保留。
- 同一轮重复交付同一文件只显示一张卡片；不同目录下同名的文件分别显示。
- 重新加载页面后的渲染结果与首次一致；Host 重启后交付卡片照常渲染，没有改动文件卡片。
- `changed-files-turn` 和 `present-svg` 录制场景以及本包单测覆盖这次合并。

## 风险

- 经软链拼写的交付，或 recorder 拼法不同的工作目录外绝对路径，不会被匹配到，仍显示两次；README 把它列为已知限制。
- 只剩头部的改动文件卡片可能显得不完整；头部保留完整数量，review 仍列出每个文件。
- 60px 高的交付卡片上，行数标签会和长文件名争空间；该标签的样式在设计定下之前保持开放。
